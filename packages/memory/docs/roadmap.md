# 开发计划

## 已实现：存储、召回与 Agent 接入

- 以 `global.long_term / space.long_term / space.daily` 表达归属与时间层级。
- 原子写入、来源、日期和过期规则、带版本检查的修改与归档。
- 中文全文、模糊、向量三路召回与 RRF 聚合。
- 持久化向量任务、重启恢复、显式重试、模型和维数隔离。
- 固定范围的 Agent 工具、预算内上下文准备、core 每次模型调用前召回。

## 下一阶段：自动整理

整理层需要明确的模型接口和可恢复的处理进度，独立于存储与检索实现。

| 流程           | 输入                       | 输出                 | 验收重点                                         |
| -------------- | -------------------------- | -------------------- | ------------------------------------------------ |
| `extract`      | session 新增消息或外部事件 | 多条带来源的记忆     | 持久化游标；与写入一起提交；重试不重复           |
| `summarizeDay` | 一个 space 的某日记忆      | 一份每日摘要         | 并发版本检查；迟到事件可重新生成；不总结摘要自身 |
| `consolidate`  | 每日事件和相关长期事实     | 新增或修订的长期记忆 | 保留来源；事实冲突与替代关系；保持空间归属       |

每个流程由 core 决定触发时机，例如会话结束、跨天或应用启动时；未完成的任务可在后续触发时补偿。它们不依赖 session 是否已经压缩，也不以单个内存定时器作为唯一执行保障。

长期沉淀保留每日原记录，创建或修订长期记录。`space.daily → space.long_term` 保持空间归属；进入 `global.long_term` 需要独立、明确的业务操作。

该阶段再引入处理游标、任务幂等记录、修订历史与事实替代关系。当前不自动执行以上流程。

## 数据规模增长后的优化

使用真实空间数量、分块数量和查询语料测量精确向量召回，再决定是否添加按模型与维数组织的 HNSW 索引。同时评估索引构建内存、启动补偿扫描、候选去重和短中文子串检索成本。

session 与 memory 目前保持独立表结构。等公共分词、向量校验与融合逻辑的需求稳定，再提取共享检索模块。
